## GitHub Release body

Faultline is a local reliability testing tool with portable experimental evidence.
Run controlled dependency-latency experiments against an isolated Docker Compose
sample, inspect baseline/fault/recovery requests and optional distributed traces,
then share recorded results as self-contained `.flb` bundles.

This first release includes:

- An offline `faultline-bundle` tool to verify, inspect and compare format-1
  evidence without Docker, SQLite, Jaeger, network access or an account.
- Versioned experiment specifications, local SQLite history and a read-only
  dashboard, available through the source checkout.
- Bounded measurements, owned fault cleanup, cancellation, raw-sample validation
  and explicit missing/partial evidence.

**Primary binary scope:** the four offline packages for macOS ARM64/AMD64 and
Linux ARM64/AMD64, plus their SHA256SUMS. macOS ARM64 ran natively; macOS AMD64 ran
under Rosetta 2; Linux ARM64 ran in a Linux VM; Linux AMD64 ran under Docker
emulation. Emulation does not qualify physical Intel hardware or every OS version.
Windows and other native CLI/dashboard packages are unsupported. The macOS ARM64
native package is not recommended as a first-release asset.

**Before installing on macOS:** these binaries have no Developer ID signature or
notarization. Gatekeeper assessment rejected the candidates. ARM64's linker ad-hoc
signature does not authenticate a publisher; AMD64 is unsigned. Locally extracted
execution tests do not prove downloaded binaries will be allowed. Follow your
organization's policies; use a reviewed source build if needed, not an automatic
Gatekeeper bypass. Publishing unsigned macOS downloads requires explicit owner
acceptance of this limitation.

Choose the matching archive, compare its SHA-256 with the manifest, extract into
a new directory, then verify the member manifest:

```sh
./faultline-bundle --version
./faultline-bundle verify left.flb
./faultline-bundle inspect left.flb
./faultline-bundle compare left.flb right.flb
```

Compare exit 0 includes valid non-comparable evidence; inspect
`assessment.classification` and `assessment.descriptive_deltas_available`.
Deltas are right-minus-left, durations in milliseconds and failure-rate differences
in percentage points. Missing evidence and undefined relative changes are explicit.
Differences are descriptive, not statistical significance or causal conclusions.
Checksums detect inconsistency, not publisher authenticity or coordinated tampering.
Trace IDs are references; temporary Jaeger traces are not bundled.

Full fault injection still requires the source checkout, local Docker Compose and
the isolated wrapper. It targets only Faultline's sample services. This is early
developer tooling, not production chaos infrastructure. See the repository's
installation/demo instructions and SECURITY.md before use. MIT licensed.

## Maintainer publication checklist

- Approve the release-facing documentation, including publication-neutral package
  instructions, the missing third-party license/notice appendix, and warnings
  applying to **all** macOS executables. Do not publish the historical 2026-10-25
  archives, which contained only Faultline's own MIT license.
- Decide whether the unsigned macOS offline experience is acceptable. If not,
  defer those assets or qualify a trusted signing/notarization process separately.
- Rebuild/reverify from the approved documentation merge SHA; do not substitute
  unreviewed source or relabel the older candidate packages.
- Publish only the four approved offline archives and a manifest listing exactly
  that asset selection. The separately built native candidate stays local.
- Recheck version uniqueness and obtain explicit owner authorization to tag and
  publish. This document authorizes none of those actions.
